# CONTEXT — the domain language of this repo

One line per term, using the meaning the code actually implements. Where the repo's
meaning is narrower than common usage, that is stated. The full contracts live in
`DESIGN.md`, `docs/DATA_WORKFLOW.md`, `docs/api/README.md` and `app/methodology/page.tsx`.

| Term                    | Meaning in this repo                                                                                                                                                                                                                                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CVE**                 | One published record from CVE List V5, pinned to a Git revision, stored in `cve_records`; the unit of every list, with a `state` of `PUBLISHED` or `REJECTED`.                                                                                                                                                    |
| **KEV**                 | CISA's Known Exploited Vulnerabilities catalog, imported as a complete validated snapshot in `kev_entries`: membership, catalog date added, due date, required action, vulnerability name, CWEs and catalog-stated ransomware use.                                                                                |
| **EPSS**                | FIRST's daily exploit-probability score (0–1) and its ordinal percentile, stored per `score_date` and `model_version` in `epss_daily`; a missing score stays `unknown`, never zero.                                                                                                                               |
| **SSVC**                | CISA Vulnrichment's SSVC decision points (Exploitation, Automatable, Technical Impact) in `ssvc_records`; an enrichment, not a score, with its own source version and timestamp.                                                                                                                                  |
| **cohort**              | The eligible set a request is scoped to before ranking and paging — the records that pass the date/severity/EPSS/KEV filters — reported as `eligibleCohort` (API coverage) or `cohortCount`/`cohortId` (checkpoint manifest), never a sample.                                                                     |
| **band**                | A display bucket, not a score: the severity band derived from the primary CVSS alone (`critical`, `high`, `medium`, `low`, `none`), plus `legacy` for CVSS 2.0 and `unknown` when no primary exists; never a composite or model-derived number.                                                                   |
| **exploit signal**      | A CVE reference the publisher itself tagged as exploit material (CNA or ADP container); the UI says "tagged", never "verified PoC", because the tag is a publisher classification and not proof of a working exploit.                                                                                             |
| **checkpoint**          | A retained Radar snapshot written once per UTC day by the ingestion worker, holding at most `CHECKPOINT_TOP_N` (default 500) ranked entries per retained view plus source pins, policy version and `boundedTopN`; immutable, never written in a request.                                                          |
| **acceptance ledger**   | The append-only `sync_runs` table: the accepted revision/version of each source; the authority for "did the inputs move?", because `MAX(source_revision)` over rows is a lexicographic coincidence after an incremental import.                                                                                   |
| **aggregate cache**     | The precomputed overview/priority snapshot in `aggregate_cache`, keyed by cache version plus the four accepted source versions; readers fall back to live queries when it is absent, stale, or its inputs moved.                                                                                                  |
| **snapshot / revision** | A pinned upstream state — a Git SHA for the CVE list, the observed catalog date for KEV, `score_date@model_version` for EPSS, a source revision for SSVC — recorded against the import that accepted it.                                                                                                          |
| **priority list**       | One of the named ranked views served by `/api/v1/priority/{listName}`: `known-exploited`, `highest-forecast`, `new-critical`, `rising-forecast`, `kev-due-soon`, `ssvc-active`; ordering is fixed per list, and no list produces a composite score.                                                               |
| **watch list**          | CVE IDs starred in one browser (local storage) and hydrated from the retained snapshot on each visit; no account and no server-side record, so it is not a saved list the API can serve.                                                                                                                          |
| **replay**              | Reading a priority list as it stood at a retained checkpoint (manifest, ordering, policy version, `boundedTopN`) instead of as it stands now; when no checkpoint is retained the page says so and labels its links as current.                                                                                    |
| **retention window**    | The `EPSS_RETENTION_DAYS` window (default 45, floor 30) in whole UTC days ending at the accepted score date; only `epss_daily` is pruned by time, while records, KEV entries and tombstones are bounded by the corpus.                                                                                            |
| **inspectable data**    | The `DESIGN.md` §7.0 contract: every mark is a pointer and keyboard stop with a text alternative, the tooltip has a fixed shape, the exact value never exists only on hover, and a measured dense-series exception is recorded rather than silently relaxed.                                                      |
| **assistant**           | The v4 research desk at `/assistant` and its one endpoint, `POST /api/assistant/chat`. Deliberately outside `/api/v1` (which stays `GET`-only), stateless, with the transcript held in the browser; the feature runs only when `AI_ENABLED=true`, a key is present, and the daily budget has headroom.            |
| **tool call**           | One invocation of a registered read-only tool by the model, dispatched by `src/lib/ai/tools.ts` after argument validation, capped by rows and time, and recorded as one line in the turn's evidence ledger. No tool writes, opens a path, or runs a command.                                                      |
| **evidence ledger**     | The per-turn list of tool calls with their arguments, row counts and returned record ids, shown beside the answer (`AssistantLedger`); the element a reader uses to check that the answer is grounded. Not the **acceptance ledger**, which records accepted upstream revisions.                                  |
| **untrusted data**      | Anything a tool retrieved — descriptions, references, fetched pages, vision output — treated as data and never as instructions, and wrapped in the untrusted envelope before it reaches the model. It can be cited as `dataset` or `web`; it can never add a capability.                                          |
| **session budget**      | `AI_SESSION_BUDGET_TOKENS` (default 60000): the estimated token total this browser transcript may spend before the next turn is refused. It is a transcript limit, never money, and it resets with a new transcript.                                                                                              |
| **daily budget**        | `AI_DAILY_BUDGET_USD` (default 5) compared against the `list_cost` summed per UTC day in `ai_usage`, so a restart cannot reset it. Exhaustion is reported as `over-budget` at the gate and `AI_BUDGET_EXHAUSTED` on a turn, with the 00:00 UTC reset instant.                                                     |
| **grounded answer**     | An answer whose numbers are supposed to come only from that turn's tool results (a prompt rule) and whose record mentions are the server's `citations` event, intersected with ids the tools returned (code). An unanswerable question is a grounded answer too: it names the query and its row count (`0 rows`). |
